## Что исправлено локально

1. `/catalog/demo/venues` требует платформенного администратора. В production действуют общие требования admin 2FA. Страница `/investor/venues` больше не подмешивает research JSON из локального файла и не отдаёт данные серверным HTML гостю: она делает авторизованный запрос в браузере, а при смене токена очищает карточки. `robots noindex` сохранён как дополнительный сигнал, а не как контроль доступа.
2. Публичные `/venues/{id}` и `/artists/{id}` отдают только открытые слоты **после** применения busy-наложений через `open_slots_unmasked`; точные `busy/held/confirmed`, iCal UID и время чужой брони доступны только члену своей организации либо платформенному администратору с действующим TOTP step-up. Для опубликованного профиля администратор без step-up получает только публичную проекцию; неопубликованный профиль остаётся закрытым.
3. Публичные фотографии площадки требуют одновременно допустимого статуса прав и индивидуальной аттестации времени/представителя для **каждой** выдаваемой строки. Владелец по авторизованному API видит и неаттестованные фото для проверки. Неаттестованные фото не попадают в публичный cover поиска и detail.
4. Сырой `Venue.details_json` может содержать исследовательские контакты и внутренние поля. Публичная проекция теперь не отдаёт его; член организации и администратор после step-up видят исходные данные.
5. Повторный импорт сбрасывает аттестацию фотографии при изменении источника или статуса прав; неизменный `owned` сохраняет аттестацию. Busy-наложения поиска считаются отдельно для каждого зала, включая поиск без даты. Авторизованный предпросмотр черновика вынесен в `/cabinet/preview/*`.
6. Смена токена или организации в той же вкладке сразу убирает данные предпросмотра; отложенный ответ прежней сессии не возвращает их после переключения туда и обратно. Тест сеттеров событий и четыре адресных browser-сценария прошли после этого уточнения.
