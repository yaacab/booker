# Помощник с контекстом связанной брони — локальный результат

В Deal Room добавлена ссылка «Помощь по этой брони». Она открывает отдельную
сессию помощника с `related_type=booking` и конкретным `related_id`;
обычная сессия поддержки пользователя остаётся отдельной. Восстановленная
из локального хранилища сессия сверяется с ожидаемой бронью.

API при создании и при каждом обращении проверяет участие пользователя в
связанной брони. На вопрос о статусе помощник читает текущий серверный
`Booking.status` и называет только этап. Он не меняет бронь, не утверждает
денежный факт и предлагает человека при расхождении статуса с ситуацией
пользователя. При отсутствии явной связи ответ остаётся общим. Статусы
платежа, возврата, спора и суммы в этот read-only ответ не включены.

Локальная проверка: API-набор поддержки и объектных прав — **77 PASS**;
TypeScript и Next production build — PASS; Ruff и diff-check — PASS.
Синтетическая БД подтверждает отказ постороннему аккаунту и новый ответ
после изменения статуса. Денежный вопрос остаётся на ветке передачи человеку.
Изолированный браузерный тест с подменённым ответом — **1 PASS** на временной SQLite и loopback:
проверены передача связанного `related_id`, отдельный ключ сессии и отсутствие
восстановления обычного диалога. Дополнительно **1 PASS** на новой временной
SQLite с реальной тестовой бронью и без подмены API: Deal Room → поддержка →
серверный этап, затем 404 для постороннего на чтение сессии и попытку
связать эту бронь со своей сессией. Staging и production ещё не проверены.
