# Просроченный первый ответ: локальный кандидат

После истечения уже рассчитанного `response_due_at` отдельный обработчик
`booker_api.support_escalation` проверяет открытые тикеты без ответа персонала.
Условное обновление `state_version` и повторная проверка ответа внутри SQL
позволяют отметить каждый тикет один раз; совместный commit сохраняет
`overdue_escalated_at`, системное событие и адресные уведомления действующим
администраторам. При отсутствии администратора с подтверждённым email и TOTP
тикет не помечается доставленным: обработчик возвращает `no_admin=1` и код 2.

Уведомление в кабинете содержит только статический текст и ID тикета. Оно
не раскрывается автору обращения или бывшему администратору после отзыва роли;
действующий администратор открывает операторскую очередь для деталей. Повторный
запуск не создаёт повторных событий. Самостоятельные
ответы и закрытые тикеты не эскалируются. Счётчик локального ops-монитора
остаётся read-only; новый обработчик запускается отдельно.

Миграция `a07f89e01f23` после `a06f78d90e12` добавляет nullable поле и
сохраняет исторические строки как неэскалированные. Manifest остаётся
`draft/manual_block`; фактический source revision, backup/restore, PostgreSQL
rehearsal и staging не проверены. Скрипт и cron находятся только в репозитории
и не установлены на сервере.

принятие срочного тикета в отдельный срок и реальная доставка по SLA остаются
