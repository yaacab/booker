# Адресные уведомления о безопасности — локальный кандидат

**Статус:** локальный код, без публикации, staging, SMTP и production проверки.

Уведомления `security.totp_enabled`, `security.totp_rotated`,
`security.recovery_codes_regenerated`, `security.totp_recovered` и
`security.password_reset` создаются в той же транзакции, что и изменение
доступа. В таблице `user_notifications` сохраняются только получатель,
имя проверенного шаблона, тип/ID события и время. Текст интерфейс строит
из статического словаря. При настроенном SMTP в outbox попадает только
статический текст, без кода, ссылки или TOTP secret. Email отправляется
отдельным worker после фиксации транзакции.

Для обычных уведомлений `request.created` и `offer.created` in-app audit
transport также создаёт адресную строку без свободного текста. Лента
`GET /notifications` сначала читает строки текущего пользователя по индексу;
исторические audit события совместимо фильтруются по адресату до LIMIT и
перепроверяются после разбора JSON. Dev inbox остаётся временным и закрытым
для production.

Миграция `a05f67c89d01` после `a04f56b78c90` проверяет существующую
таблицу перед принятием runtime схемы и не разрешает автоматическое удаление
уведомлений при downgrade. Manifest остаётся `draft/manual_block`; фактические
backup/restore, источник БД и PostgreSQL rehearsal ещё нужны до выпуска.

**Открыто:** SMTP delivery на staging, уведомления о новом устройстве,
привязке/отвязке способов входа, изменении ролей и адреса, а также полный
recovery/identity путь. Этот локальный блок сам по себе не закрывает S06
или критерий полного запуска; шкалы остаются 59,00% / 56,00% / 15,00%.
