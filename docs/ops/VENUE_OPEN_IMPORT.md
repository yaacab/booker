# Каталог площадок Москвы из открытых источников

Источник импорта: [`data/moscow_performance_venues_research.json`](../../data/moscow_performance_venues_research.json). Набор содержит 300 уникальных московских площадок, отобранных для выступлений артистов: у каждой есть реальный адрес, вместимость, описание, числовая почасовая цена, контакт и пять внешних фотографий со ссылкой на исходную карточку. Это исследовательская витрина для инвесторского демо. Все записи остаются в статусе `needs_review` и не попадают в рабочий поиск без календаря и подтверждения представителя площадки.

## Жизненный цикл карточки

У карточки отдельно хранятся происхождение данных, модерация и отношения с площадкой:

- `source_type`: `automated_import` или `owner_submission`;
- `partnership_status`: `unverified_listing`, `claimed`, `verified`, `partner`;
- `moderation_status`: `published`, `needs_review`, `rejected`, `archived`;
- `data_freshness_status`: `fresh`, `aging`, `stale`, `needs_review`.

Автоматически созданная карточка начинает со статуса `unverified_listing`. В публичном интерфейсе она получает подпись «Информация из открытых источников». После подтверждения или начала сотрудничества подпись исчезает, при этом `source_type` и история источников сохраняются.

## Что делает импорт

1. Создаёт служебную организацию «Букер · открытый каталог Москва».
2. Ищет существующую карточку по URL источника, точному имени и составному сигналу дубля.
3. Записывает основные поля, координаты, контакты, параметры площадки и условия аренды.
4. Сохраняет URL и дату проверки источника в отдельной таблице.
5. Сохраняет внешние фотографии только вместе с URL исходной карточки и статусом прав; `unknown` доступен лишь отдельной демо-витрине, но не публичному каталогу.
6. Рассчитывает полноту карточки по 100-балльной шкале.
7. Допускает карточку к публикации только при наличии содержательного описания, официального сайта/контакта, цены с отдельным источником и фотографии со статусом `licensed` или `official_permission`.
8. Не создаёт автоматические слоты: календарь может открыть только представитель площадки.
9. Записывает результаты в журнал партий импорта.
10. При повторном запуске обновляет данные без создания дублей и без сброса статуса партнёрства.

## Поля расширенного набора

Сборщик сохраняет тип и округ, координаты, площади и варианты вместимости, тариф, минимальный чек и депозит, правила еды и алкоголя, кухню, парковку, сцену, звук, свет, экран, гримёрки, Wi-Fi, доступность, ограничения по шуму, контакты, официальный сайт, социальные ссылки и фотографии с происхождением и правами.

## Команды

```bash
make seed-venues-moscow
make seed
```

Повторный запуск идемпотентен. На текущем наборе первый импорт создаёт 300 исследовательских карточек и записи об источниках; второй обновляет те же карточки без дублей. Автоматические слоты не создаются. Инвесторская витрина доступна по `/investor/venues`, её API — `GET /catalog/demo/venues`; обе части явно отделены от `/catalog/search`.

## Обновление исследовательского набора

```bash
node scripts/fetch_speedrent_performance_venues.mjs \
  --limit 300 \
  --max-loft-pages 20 \
  --concurrency 16 \
  --output data/moscow_performance_venues_research.json

node scripts/validate_moscow_performance_venues.mjs \
  data/moscow_performance_venues_research.json \
  --online

make seed-venues-moscow
```

Сборщик начинает с официального фильтра концертных залов SpeedRent, затем проверяет лофты и танцевальные залы. Карточка проходит только при наличии числовой цены, фотографии, описания от 80 символов и концертной/танцевальной категории либо минимум двух сценических сигналов. Тренинговые, консультационные, детские, фитнес-, фото- и подкаст-пространства исключаются. LOFT HALL используется как официальный операторский источник, EventCatalog — как независимый источник специализации и адресов для дальнейшей перекрёстной проверки.

## Работа модератора

В административном разделе отображаются общие показатели и первые 50 карточек. Для каждой карточки можно:

- перевести отношения в `unverified_listing`, `claimed`, `verified` или `partner`;
- опубликовать карточку или вернуть её в `needs_review`;
- увидеть число источников, полноту и свежесть данных.

API административного раздела:

- `GET /admin/venue-catalog/report`;
- `GET /admin/venue-catalog/venues`;
- `GET /admin/venue-catalog/venues/{id}/history`;
- `POST /admin/venue-catalog/venues/{id}/status`;
- `POST /admin/venue-catalog/venues/{id}/moderation`;
- `POST /admin/venue-catalog/freshness/recalculate`;
- `GET /admin/venue-catalog/batches`.

Каждая смена статуса сотрудничества записывается в историю с автором, временем и комментарием.

## Регламент из 15 блоков

1. Определить категории, округа и целевой размер партии.
2. Собрать кандидатов из официальных сайтов, OSM, Wikidata и data.mos.ru.
3. Отделить первичные источники от поисковых подсказок.
4. Заполнить минимальные поля: имя, адрес, тип, источник.
5. Добавить вместимость, тарифы, контакты и официальный сайт.
6. Добавить инфраструктуру и условия проведения событий.
7. Добавить фотографии только с источником и статусом прав.
8. Нормализовать имена, адреса, телефоны, домены и координаты.
9. Найти дубли по URL, имени, адресу, телефону, домену и близости координат.
10. Рассчитать полноту и отправить слабые карточки на проверку.
11. Импортировать партию и сохранить её отчёт.
12. Проверить публичный каталог и подпись открытых данных.
13. Обработать заявки владельцев и подтверждение площадок.
14. Пересчитывать свежесть раз в квартал, возвращать устаревшее на проверку.
15. Сводить покрытие по источникам, ценам, контактам, фото, модерации и партнёрству.

## Источники и права

- OpenStreetMap: ODbL.
- Wikidata: CC0.
- data.mos.ru: условия портала открытых данных Москвы.
- SpeedRent: источник карточек, заявленной почасовой цены и внешних фотографий для инвесторского демо.
- LOFT HALL: официальный операторский источник по форматам концертов и техническому оснащению.
- EventCatalog: независимый каталог для поиска и перекрёстной проверки специализации.
- Цена из открытого источника является ориентиром. Итоговая коммерческая сумма фиксируется только в версии оффера.
- Внешние фото имеют статус `unknown`, показываются только в noindex-демо с атрибуцией и не проходят фильтр публичного каталога. Для публичного запуска нужны `licensed` или `official_permission`.
