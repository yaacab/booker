## Локальные артефакты и gate

`infra/schema-release-manifest.v1.json` — **draft**, а не разрешение. Он фиксирует порядок ID, путь и SHA-256 каждого файла, исходную ревизию c8, целевую вершину `ffbc123cd4e6` и классификацию; поля владельца, хеша репетиции и data backup пусты. Текущий SHA-256 черновика: `5da4f3ec9130e1f46ba36465cd632502e8879275ebd128e6c9f3513f255bd965`; SHA-256 ревизии ff: `e6139300398082fee80ba97b2ee9dea81c67702c1c48cdd7e5468ed7f57283fd`. `infra/schema_release.py` проверяет одну цепочку без разрывов/ветвлений, точные хеши, известную исходную ревизию и внешний exact hash утверждённого манифеста. Текущий черновик закономерно отклоняется из-за `manual_block` после c8. Обхода классификатора путём заполнения полей нет.

`infra/release_deploy.py` при изменении DB/model/migrations требует защищённые `BOOKER_SCHEMA_*` значения, точный манифест, отдельное evidence предварительной миграции, совпадение source revision, backup/rehearsal hashes и фактическую target revision **активной SQLite**. PostgreSQL URL блокируется явно: устаревший SQLite-файл не может служить доказательством рабочей PG. Отсутствие evidence, неизвестная schema и текущий `manual_block` закрывают выпуск. Он **не запускает** миграции сам: это отдельная pre-switch фаза с проверенной копией, backup v2, планом остановки записи/совместимости и владельцем. После миграции откат кода не откатывает DB; при несовместимости нужен отдельный data restore plan.

## Следующий контрольный шаг

1. В отдельном разрешённом read-only окне определить фактический engine, точный `alembic_version` (включая отсутствие/несколько строк), schema fingerprint, сохранность критических строк и реальный deployed code SHA; записать без секретов. Никаких stamp по сходству таблиц.
2. Для каждой обнаруженной исходной версии и неверсированной legacy-схемы подготовить отдельную репетицию на подтверждённой копии. Разобрать каждый `manual_block`, финансовые значения и необратимость. Добавить PostgreSQL в отдельной test schema.
3. Владелец данных утверждает точный манифест, совместимость old/new API, окно записи, sealed backup/restore v2, RTO/RPO и план остановки/отката. Evidence связывает observed before, архив, репетицию и target. Только после этого возможна отдельная миграционная фаза и затем release switch.
