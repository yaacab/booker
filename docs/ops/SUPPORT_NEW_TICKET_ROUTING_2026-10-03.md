# Маршрут нового обращения — локальный кандидат

Новый тикет из формы поддержки и явная передача из помощника теперь создают
адресное уведомление **в той же транзакции**, что и обращение. Если настроен
активный основной оператор с подтверждённой почтой и TOTP, статический сигнал
попадает ему в кабинет. Без такого оператора сигнал получают действующие
администраторы с подтверждённой почтой и TOTP. Уведомление не означает взятие
тикета в работу: принятие и ответ остаются отдельными действиями человека.

Для `high`/`urgent` при активной email-настройке того же адресата и SMTP
создаётся только запись в `EmailOutbox`. Тема и тело фиксированы; вопрос,
имя, контакты и данные сделки в письмо не входят. Перед отправкой worker
сверяет роль, подтверждение адреса, TOTP, активную настройку, открытый тикет,
отсутствие ответа оператора, приоритет, текст письма и окно 10:00–22:00 МСК.
Для основного оператора дополнительно сохраняется требование активного
кабинетного адресата. Неопределённый исход SMTP получает `uncertain` и не
повторяется автоматически.

Операторскому сеансу открыт только `GET /notifications`; серверный allowlist
для остальных маршрутов не расширен. После отзыва операторской роли
служебное уведомление в личной ленте больше не выдаётся. В верхнем меню web
для новых обращений есть переход в очередь поддержки. В локальном
ops-monitor агрегированный сигнал `support_without_eligible_staff` показывает
открытые обращения без ответа, если нет ни основного оператора, ни доступного
администратора. Текст и адреса в сигнал не попадают.

Локальная проверка точного среза: полный API — 756 PASS/9 SKIP; адресные
тесты маршрута, ACL, email и мониторинга — 21 PASS; браузерный путь помощника
с проверкой адресного сигнала администратору — 1 PASS на временной SQLite;
web TypeScript, 21 модульный файл и production build — PASS. Код и тесты
локальны; реальных писем не отправляли. Telegram,
фактический Павел, резервная смена, внешний канал сигналов, cron, staging и
production не подтверждены. `P05` уже учтён в прогрессе; `O06` требует
реальной среды и адресата, поэтому 59,00% полного запуска не меняются.
