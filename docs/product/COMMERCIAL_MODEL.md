# Коммерческая модель Букера

Основание: OWNER DIRECTIVE 2026-09-12. Product Contract v3 — источник правил.
Реализация коммерческого запуска продолжается; приёмка — [PRELAUNCH_V1.md](PRELAUNCH_V1.md).

## Каталог и тарифы

Стартовые значения заданы в `apps/api/booker_api/commerce/catalog.py`,
персистентные ревизии — `commercial_plans` и `promotion_products`.
Публичный `GET /commerce/catalog` возвращает цену в RUB, годовую экономию,
ставки в basis points, возможности, их русские подписи и версию.

- Артист Free / Pro / Premium: 0 / 1 990 / 4 990 ₽ в месяц;
  год: 0 / 19 900 / 49 900 ₽.
- Площадка Free / Pro / Premium: 0 / 3 990 / 7 990 ₽ в месяц;
  год: 0 / 39 900 / 79 900 ₽.
- Заказчик Standard / Business: 0 / 4 990 ₽ в месяц, 0 / 49 900 ₽ в год.

Изменение тарифов через `PUT /admin/commerce/plans/{code}` требует platform admin,
проверки второго фактора по существующей политике, expected_version и причины.
Старая ревизия не удаляется. Повтор со старой версией возвращает конфликт.
Базовый тариф нельзя сделать платным или лишить основного доступа.

## Сборы по сделке

Сервер определяет тариф каждой стороны в момент публикации версии предложения.
Заказчик платит гонорар + 6%; исполнитель получает гонорар минус 4%/3%/2%.
Доход платформы — оба сбора. Округление каждой комиссии независимо half-up до рубля,
через `(honorarium * bps + 5000) // 10000`; float в арифметике не участвует.

Оффер хранит все денежные результаты и `commercial_policy_version`.
`commission_rub`/`total_rub` — совместимые алиасы сбора/итога заказчика.
Исторические версии не пересчитываются; новые поля у них NULL. DB trigger
защищает денежные условия и текст версии от UPDATE, разрешая ack.

## Доступ по подписке

`get_entitlements(db, organization_id)` — единая точка разрешения возможностей.
Active/trial работают только внутри оплаченного/выданного периода. Pending,
past_due, cancelled, expired дают Free. Отключённый commercial flag также
не лишает Free основного booking-сценария.

Pro: аналитика 90 дней, фильтры и alerts заказов, расширенное портфолио/география,
2 Boost, 2 участника. Premium: 365 дней, benchmark, 8 Boost, Featured,
5 участников, экспорт и приоритетная поддержка. Business: команда, шаблоны,
аналитика, заметки, история поставщиков и экспорт документов.
Наличие feature code ещё не означает приёмку UI/API конкретной функции:
покрытие фиксируется отдельно в PRELAUNCH_V1.

## Заказы и оплата

`created → pending_payment → paid | failed`; неоплаченный заказ можно отменить;
подтверждённый провайдером полный возврат переводит paid в refunded.
Платный тариф активируется только по проверенному событию с совпадением
order id, provider reference, RUB и полной суммы заказа.
Provider event id уникален; повтор возвращает сохранённый ответ, подмена
payload под старым event id — конфликт. Поздний failed не отменяет paid.

Idempotency key scoped к организации. Другие параметры с тем же ключом — 409.
Пока есть незавершённый заказ подписки, второй не создаётся. Организация
блокируется в транзакции и на SQLite, и на Postgres.

Отмена подписки действует на конец периода. Понижение сохраняет выбранный
next_plan_code, текущие возможности работают до окончания периода. Новый
платный период требует успешной оплаты; без неё действует Free. Повышение
оплачивается как новый полный период с момента подтверждения, без
автоматически рассчитанных доплат/возвратов за остаток старого периода.

Ручной grant/revoke администратора имеет provider=manual и аудит с причиной;
он не создаёт доход или фиктивный paid order. Реальные поступления, тестовые
платежи и начисленная комиссия должны отображаться раздельно.

## Продвижение и доверие

Стартовые Boost 24h/72h/7d/Featured 7d: артист 490/990/1990/4990 ₽,
площадка 990/1990/3990/9990 ₽. Все цены — серверные ревизии.

Обязательная политика выдачи: сначала обычные strict filters и реальная
доступность, затем sponsored insertion; максимум 20%, не две подряд,
маркировка «Продвижение». Органический порядок хранится отдельно.
Атрибуция должна связывать impression → click → request → booking с кампанией
и подтверждёнными серверными фактами, не с произвольным клиентским счётчиком.
Реализация ranking/атрибуции принимается отдельно.

Verified, отзывы, рейтинг, завершённые сделки и время ответа не продаются.
Free имеет доступ к самим подходящим заказам; подписка продаёт инструменты.
Нет продажи контактов, платы за лид, рекламы третьих сторон или AI-решений по спорам.

## Paid promotion и атрибуция

`commerce/promotions.py` вставляет платные карточки **после** обязательных фильтров
каталога. Недоступные профили не добавляются обратно. Не более `floor(N / 5)`
карточек на выдачу, позиции разделены органическими карточками; исходный порядок
доступен как `organic_rank`. При N < 5 платных позиций нет. Для площадок требуются
published, claimed и календарь owner; synthetic-календарь не даёт права на рекламу.
Оплата не влияет на verified, отзывы, рейтинг и факты профиля.

Включённые Boost — 24 часа, квота 2/8 по тарифу, календарный месяц UTC.
Списание фиксируется в `promotion_credit_uses` при запуске; отмена не восстанавливает
кредит. Платная кампания начинается только после проверенного события оплаты;
непригодный к моменту оплаты профиль получает rejected с audit refund_required.
Остановка активной кампании прекращает показы, но сама по себе не означает возврат
денег. Возврат отражается только после подтверждения провайдера.

Каждая платная карточка получает непрогнозируемый `promotion_touch_id`, действующий
7 дней. Браузер отправляет impression при видимости >=50% и click при переходе.
Каждое событие для token учитывается один раз. Заявка атрибутируется только на сервере,
при совпадении профиля с реально созданной заявкой после клика. Заявки участников
самой supply-организации исключены. Бронирование учитывается после Confirmed,
повторные callbacks не увеличивают счётчик. Просмотр кабинета и отметка «оплачено»
в UI не создают конверсий. Метрики переходов отражают клиентские сигналы, а не
подтверждённых уникальных людей; отдельная защита от рекламного фрода не заявляется.

Admin `PUT /admin/commerce/promotions/{audience}/{code}` создаёт новую ревизию цены
с expected_version и причиной. Суммы уже созданных заказов остаются прежними.
Никакие реальные списания и массовые рассылки этим инкрементом не подключаются.

## Витрина артиста / EPK

Free сохраняет полноценную страницу: обложка, основное видео, 6 фотографий,
3 дополнительные видео/аудиозаписи, программа/жанры/состав/продолжительность,
текстовый и структурированный райдер, до 3 городов выезда, календарь, пакеты,
отзывы и реальные факты. Pro/Premium разрешают до 24 фотографий, 12 записей,
30 городов и порядок «сначала портфолио». Лимиты возвращает API через существующие
`portfolio.advanced` / `geography.advanced` entitlements. Снижение тарифа сохраняет
материалы, запрещает наращивать объём выше лимита и возвращает публичный порядок
блоков к стандартному. Редактирование остального профиля остаётся доступным.

Владелец подтверждает право публиковать медиа. Принимаются публичные HTTPS-ссылки;
сервер не скачивает произвольные URL. ArtistPresentation имеет отдельную версию,
оптимистическую проверку и audit. Правки не затрагивают OfferVersion, verified,
отзывы или календарные записи. Опубликованный тариф — ориентир, не счёт.

Отзывы публичного профиля выбираются по его собственным Completed bookings,
включая hall→venue. Отзывы других артистов той же организации не переносятся.
Средняя оценка появляется от 5 отзывов; отдельные реальные отзывы доступны раньше.
Публичная выдача отзывов не раскрывает user/booking IDs. Подписка не меняет этот путь.
