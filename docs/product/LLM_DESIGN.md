# Букер — бриф для дизайна (публичный)

Сайт: https://bukergo.ru
Бренд: Букер (не BOOKED, не THE AIV). Канон домена bukergo.ru.

## Задача для модели

Продумать визуальную систему и UX всего продукта. Текущий UI — рабочий каркас MVP, не финальный дизайн. Нужен целостный дизайн: лендинг, каталог, карточка артиста, заявка, кабинет, Deal Room, логин, админка, юридические страницы, мобила.

Не ломать продуктовые правила ниже.

## Продукт

Операционная система сделки: дата → цена → договор → оплата. Не классифайд и не Airbnb.
Букер — агрегатор: не артист и не площадка.
Concierge-first. Цена только с сервера (quote_id). Нет выдачи без календаря.
Protect / «страхование» — не в MVP. AI не решает споры.

## Текущие токены (как на проде)

- Петроль бренд #2D6A66 / hover #245853
- Графит / ночь #151817, холст #F3F0E9, поверхность #FAF8F3, бордер #E0DBD2
- Золото #B58A46 — только hold, ожидание, точка эмблемы
- Циан #18B8C9, успех #159B68, янтарь #B7791F, опасность #C24156 — статусы, не бренд
- Шрифты самохостятся: Manrope + IBM Plex Mono. Герой ~40px. Радиус 16px.
- Эмблема: три фигуры + золотая точка, `public/mark.svg`.
- Мобила <768: нижняя панель — знак / Свободные / Вечер / Сделки / Я. Sticky CTA на карточке артиста, площадки и в гримёрке.
- Нет кастомного курсора, нет heavy-motion. Предпочитать ясность и доверие, не «вау-лендинг агентства».
- Первая сделка заказчика: комиссия платформы 0, гонорар как есть. Цена только с сервера.

## UX-инварианты

- Quote всегда с сервера, на экране виден quote_id, гонорар, комиссия, итог. Комиссия 0 — чип «первая сделка».
- Deal Room (в UI «гримёрка») вкладки: Чат / Условия / Документы / Платежи / Спор / Этапы.
- Спор — выбор категории, не свободная форма. Решение — оператор, не ИИ.
- Прямой перевод вне платформы снимает защиту сделки.
- Календарь и поиск по дате — сутки Москвы, не UTC. Дата из выдачи едет в карточку артиста и площадки (`?date=`), нужный день помечается.
- С площадки «собрать вечер» передаёт имя крыши в черновик (`?roof=`).
- Мобильный приоритет заказчика: поиск → вечер/заявка → статус → чат.

## Что спроектировать

1. Визуальный язык (типографика, сетка, цвет, свет/тьма если нужно).
2. Компоненты: кнопки, поля, карточки артиста, quote-блок, таймлайн брони, табы Deal Room.
3. Состояния пусто / загрузка / ошибка / hold истёк / спор.
4. Навигация ролей: заказчик / артист / площадка / админ.
5. Доверие: агрегатор, не страхование, живой оператор.
6. Адаптив 375 / 768 / 1280.

Ответ: система + ключевые экраны (описание или ASCII/структура), не код, пока не попросят.
