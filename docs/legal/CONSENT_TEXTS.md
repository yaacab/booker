# Тексты согласий в интерфейсе

**Статус:** черновик редакции `2026-10-01`. Короткие формулировки для проверки юристом; до утверждения не являются готовыми UI-текстами.

Версия пакета, которая должна уходить в аудит при регистрации: `2026-10-01-draft` вместе с временем, user ID, IP/User-Agent в допустимом объёме и идентификатором каждой принятой редакции.

## Обязательно при регистрации

1. После утверждения документа: «Принимаю [оферту цифровых услуг](/legal/offer) редакции [ДАТА]. Букер предоставляет цифровой сервис и не является исполнителем выступления или арендодателем площадки.» До утверждения вместо акцепта: «Ознакомлен с тестовыми правилами; они не являются публичной офертой, платежи через Букер недоступны».

2. «Ознакомлен с [политикой обработки персональных данных](/legal/privacy). Для операций, где основанием должно быть согласие, даю отдельное согласие на обработку перечисленных в форме данных для [КОНКРЕТНЫЕ ЦЕЛИ] до [СРОК/УСЛОВИЕ], с правом отзыва по адресу [EMAIL_PDN].» Юрист должен определить, где достаточно договора/закона, а где требуется согласие; одна универсальная галочка не подменяет все основания.

Без обеих отметок регистрация не создаётся.

## Отдельно, по умолчанию выкл.

3. «Согласен получать рекламу Букер по email [АДРЕС]. Согласие добровольное и не влияет на использование сервиса; отозвать его можно по ссылке в письме или через [КАНАЛ].» Каналы (email/SMS/мессенджер/push) перечисляются раздельно либо явно одним контролем; доказательство согласия и отзыва хранится.

## Вход

Повторный акцепт оферты при каждом входе не требуется, пока юрист не скажет иначе. Ссылка на документы — в подвале сайта.

## Восстановление пароля

Запрос email не раскрывает, есть ли аккаунт. Письмо на пилоте не отправляется.

## Deal Room / договор сторон

OTP — техническое подтверждение действия в аккаунте. Его вид электронной подписи, соглашение об использовании простой электронной подписи, способ идентификации, распределение риска компрометации и доказательственная сила должны быть утверждены юристом. До этого UI не называет OTP «подписью договора» и не сообщает, что договор заведомо действителен.
