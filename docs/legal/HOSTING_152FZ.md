# Фаза 0: хостинг и 152-ФЗ

**Статус:** инфраструктурный черновик, сверка 2026-10-01. Российский IP/диск сам по себе не доказывает выполнение всех требований 152-ФЗ.

Первичный сбор данных российских пользователей — на инфраструктуре в РФ.

## Кандидаты

| Слой | Кандидаты |
|------|-----------|
| VM / Kubernetes | Yandex Cloud, Selectel |
| PostgreSQL | Managed Postgres в том же облаке |
| Redis | Managed Redis / VM рядом |
| S3 | Yandex Object Storage, Selectel S3 |
| Наблюдение | логи в РФ; Sentry — проверить трансграничную передачу |

`infra/docker-compose.yml` — локальный Postgres 16 + Redis. Прод-кластер в этот репозиторий не зашивается.

Пилот 2026-08: приложение на VPS в РФ (см. `docs/ops/DOMAINS.md`), БД SQLite на диске сервера. Отдельного object storage ещё нет — сканы документов в продукт не принимаем.

## До публичного сбора ПДн

1. Назначить ответственного за ПДн.
2. Подать уведомление в Роскомнадзор.
3. Опубликовать политику (отдельное согласие на рекламу).
4. Регламент инцидента с актуальными законными сроками, ответственными, каналами и составом уведомлений; конкретные 24/72 часа подтверждает юрист по действующей редакции.
5. Реестр всех обработчиков и систем: email/SMS, monitoring/error tracking, backup, антивирус вложений, платёжный партнёр; проверить поручения и географию каждого.
6. Утвердить сроки хранения/backup rotation, матрицу доступа, модель угроз и процедуру запросов субъектов.

## Не делать

Хостить основную БД пользователей вне РФ «потому что дешевле».
