# Юрист: бриф на проверку

Нужен российский юрист: агрегаторы / 289-ФЗ (если применим), платёжные агенты, 152-ФЗ, ЗоЗПП, 38-ФЗ, 54-ФЗ вместе с партнёром.

Пакет: `docs/legal/README.md`. Реквизиты: `OPERATOR.md` (сейчас плейсхолдеры). Публичные зеркала: https://bukergo.ru/legal.

Контакты фирмы в репозиторий не класть.

## Проверить по файлам

1. `OFFER_DRAFT.md` — оферта цифровых услуг, акцепт, агрегатор vs исполнитель, hold, OTP, ответственность, изменение редакции.
2. `PRIVACY_DRAFT.md` — цели/основания ст. 6, сроки, права субъекта. Шрифты самохостятся (`/fonts`).
3. `COOKIES_DRAFT.md` — достаточно ли сессии без баннера.
4. `DISPUTES_REFUNDS_DRAFT.md` и four-eyes — не выдавать за судебную гарантию.
5. `SUPPLIER_TERMS_DRAFT.md` — исполнитель и площадка.
6. `CANCELLATION_TARIFF.md` — не противоречит ЗоЗПП; не делать дефолтом платформы.
7. `CONSENT_TEXTS.md` — две обязательные галочки и отдельный маркетинг.
8. Типовой прямой договор сторон (сейчас короткий шаблон в API `CONTRACT_TEMPLATE`) — заменить на утверждённую форму.
9. Схема с платёжным партнёром из `PAYMENTS_SHORTLIST.md` (агент / сервис / иное) + чеки.
10. Формулировки без «страхования».

## Вопросы, на которые в репо нет ответа

- Кто оператор по ЕГРЮЛ и налоговый режим.
- Применима ли ЗоЗПП к заказчику-физлицу на цифровые услуги Букер и отдельно к услуге артиста.
- Нужна ли регистрация информационного посредника / иные статусы 289-ФЗ.
- Достаточен ли OTP как акцепт прямого договора.
- Когда снимать баннер «платежи заблокированы».
- Уведомление РКН: состав данных пилота (аккаунт + сделка, без сканов).

## Критерий готовности гейта U5

Юрист письменно: «можно публиковать как действующие» **или** список правок. Оферта без реквизитов из `OPERATOR.md` не публикуется как действующая.
