# Фаза 0: платёжный партнёр (РФ)

**Статус:** исследовательский шортлист, проверен по продукту 2026-10-01; коммерческие условия и доступность продуктов партнёров требуют свежего RFP. Таблица не является выбором партнёра или юридическим заключением.

**Новое сведение владельца 01.10.2026:** у него есть аккаунт ЮKassa. Договор и подключённые продукты не просмотрены; `LivePaymentAdapter` в репозитории остаётся заглушкой. Поэтому ЮKassa — первый адресат проверки применимости, а не уже выбранная и интегрированная схема Букер. Не помещать shopId, секретный ключ или договор с реквизитами в этот файл.

Букер **не** эскроу-банк. Слой `PaymentProvider` + webhooks + идемпотентность + ежедневная сверка.

## Шортлист (не выбор, а кандидаты для юриста и финансов)

| Партнёр | Зачем смотреть | Ограничения |
|---------|----------------|-------------|
| ЮKassa | У владельца уже есть аккаунт; проверить обычный приём, решение для площадок и «Безопасную сделку» | Нужны отдельное подтверждение доступности/договор для конкретной схемы, лимиты, выплаты и фискализация; аккаунт не равен запуску |
| Тинькофф / Т-Банк эквайринг | Юрлица и ИП, API | Самозанятые — отдельный контур |
| Точка Банк | Агентские схемы для площадок | Проверить лимиты и оферту |
| CloudPayments | Интернет-эквайринг | Юрисдикция и 54-ФЗ |
| НКО / расчётный партнёр под безопасную сделку | Ближе к hold средств | Долгая интеграция; гейт U5 в прод |

Боевой провайдер за фичефлагом `BOOKER_PAYMENT_PROVIDER`. Режимы в коде: `stub` (CI/dev), **`external`** (diligence / concierge до U5), live-партнёр (после юриста).

## Режим `external` (до live)

- Обязательство создаётся как `Pending` / off-platform transfer; concierge/admin фиксирует предоставленное доказательство и результат проверки с audit, но не создаёт фиктивное банковское подтверждение.
- В UI: «оплата вне платформы» — без эскроу / страховки / «гаранта».
- Поддержка и спор не отключаются автоматически из-за внешнего способа оплаты; объём помощи утверждается документами.
- Webhook партнёра не принимается; путь к live описан в `docs/investors/PAYMENTS_PATH.md`.

## Пилот

- Получатели: юрлица и ИП. Самозанятые (НПД) — фаза Market fit.
- НПД владельца оператора и НПД поставщиков — разные вопросы. Статус владельца сам по себе не открывает выплаты поставщикам на НПД и не решает вопрос допустимости агентской деятельности.
- Повтор webhook с тем же `event_id` возвращает сохранённый ответ.
- Неуспешный платёж не переводит бронь в `Confirmed`.

## Гейт в прод

Юрист + бухгалтер + письменное подтверждение ЮKassa для конкретной формы оператора и многосторонних потоков + KYC + сверка + payout/refund/chargeback + чеки по применимому режиму (54-ФЗ для ККТ либо 422-ФЗ/«Мой налог» для допустимого дохода НПД) + E2E. До этого Alpha/diligence идёт на `external` или со счётом вручную с нейтральной пометкой «Букер не принимает и не удерживает этот платёж».
