## Правило подсчёта

Для **каждой** шкалы результат = сумма весов строк со статусом `✓` / сумма её фиксированных весов × 100. В каждой шкале знаменатель 100 баллов; `○` даёт 0, незавершённая работа не даёт частичных баллов. Один и тот же факт может входить в разные шкалы, но внутри одной шкалы не начисляется повторно. После закрытия критерия записать дату, точный SHA или dirty diff, проверку и уровень `локально / staging / production / внешнее решение`, затем сразу пересчитать все затронутые шкалы, изменение в процентных пунктах и остаток. Не менять веса задним числом ради роста процента; при необходимости разделить строку **до** выполнения, сохранив общий вес. Сотые — формат учёта, не точность прогноза.

Технический MVP — проверенный продуктовый путь и эксплуатация на staging **без реальных денег**; красивый сайт — утверждённый дизайн из отдельного проекта, перенесённый в работающий web и проверенный на staging; полный запуск включает также право, деньги, production и реальный пилот. Ни одна из первых двух шкал не означает готовность к коммерческому запуску. Полный запуск сохраняет прежний фиксированный реестр ниже.

## Риски, уже включённые в веса выше

- **P03/M01/O05:** PostgreSQL гонки booking/hold и первого оффера с нулевой комиссией; конкурентная отмена против webhook; денежные инварианты на исходной схеме. Локальные SQLite тесты не закрывают этот gate.
