# Критерии приёмки Event Studio Map v1

## Сценарий заказчика

- [ ] Черновик можно начать без окончательной даты, площадки и полного профиля.
- [ ] Шаги доступны назад без потери данных; неизвестные поля можно пропустить.
- [ ] Изменение города/даты пересчитывает совместимость и объясняет, кто перестал подходить.
- [ ] Можно добавить несколько специалистов одной категории и удалить одного без разрушения остальных.
- [ ] Площадка, её оснащение и выбранные подрядчики проверяются на пересечения и конфликты.
- [ ] Предупреждение можно раскрыть; блокирующее условие явно объяснено.
- [ ] Бюджет до предложений помечен ориентиром, финальная сумма получена с сервера.
- [ ] Перед отправкой доступна единая проверка состава, условий и контактных данных.

## Данные и сделки

- [ ] Event хранит общий контекст, Requirement — каждую позицию, Request/Deal — независимый процесс позиции.
- [ ] Каждая OfferVersion неизменяема и имеет `quote_id`; существенное изменение сбрасывает подтверждения.
- [ ] Двусторонние подтверждения фиксируются отдельно и только для активной версии.
- [ ] Hold создаётся серверной транзакцией, имеет TTL и не допускает двойного удержания.
- [ ] Время хранится с timezone; монтаж, демонтаж и буферы входят в проверку доступности.
- [ ] Цена, комиссия, возврат и гарант не рассчитываются в браузере.

## Надёжность и безопасность

- [ ] Повторный submit с тем же idempotency key не создаёт дубли.
- [ ] Object-level authorization проверена для Event, Request, OfferVersion, Deal и документов.
- [ ] Смена реквизитов, финансовые действия и передача workspace требуют усиленного подтверждения.
- [ ] Production не содержит demo-admin, тестовый OTP или тестовую оплату.
- [ ] Журнал действий дописываемый и не редактируется обычным оператором.

## UX, доступность, аналитика

- [ ] Desktop соответствует структуре `reference.png`; mobile использует bottom sheet.
- [ ] Все действия доступны с клавиатуры, виден focus, интерактивные элементы имеют доступные имена.
- [ ] Автосохранение показывает saving/saved/error и умеет повторить запрос.
- [ ] Пустые, loading, error, stale availability и no-results состояния спроектированы.
- [ ] Аналитика измеряет переходы между шагами, время до первой ценности, добавление позиций и submit.

## Проверка перед merge

- [ ] TypeScript typecheck.
- [ ] Production build.
- [ ] E2E: создание события с одной позицией.
- [ ] E2E: команда из нескольких позиций и частично заполненный состав.
- [ ] E2E: конкурентный hold одного слота.
- [ ] E2E: восстановление черновика и конфликт версий.
- [ ] Визуальные скриншоты desktop 1440 px и mobile 390 px.
- [ ] Старый Event Studio доступен при выключенном feature flag.
