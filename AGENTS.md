# AGENTS.md — Букер

- Бренд: **Букер**. Репозиторий: `booker`. Не смешивать с THE AIV.
- Источник правды по продукту: `docs/product/CONTRACT.md`.
- Расширенная цель по единому аккаунту (Telegram/Яндекс/VK), собственной 2FA, операторской поддержке и честному инвесторскому демо: `docs/product/IDENTITY_SUPPORT_INVESTOR_GOAL_2026-10-02.md`. Перед миграциями проверить фактическую БД, backup/rollback и staging; не выдавать локальное демо за действующий сервис.
- Цена, комиссия, возврат — только API.
- Платёжный прод — после юриста и партнёра (`docs/legal/`).
- Публичные домены: канон **bukergo.ru**; `bookergo.ru` и `bukergo.online` — редирект. DNS: `docs/ops/DOMAINS.md`.
- Текущая рабочая цель — технический MVP по `docs/DEVELOPMENT_GOAL.md`: закончить и проверить продуктовый путь, безопасность, staging и CI. Юридическую часть, реальные платежи и финансы пока не развивать; существующие защитные ограничения сохранять. Дизайн и motion делаются отдельным проектом и переносятся сюда только после утверждения.
- Когда законченная часть работы проверена и ей нужен коммит, самостоятельно фиксировать только её файлы отдельным коммитом, без повторного вопроса владельцу. Для GitHub CI открыть/обновить обозримый PR к `main`/`master`: push в текущую feature-ветку без PR не запускает этот workflow. Пока CI идёт, продолжать независимую работу; затем проверить результат на точном SHA. Не включать в коммит соседние незавершённые изменения, секреты и временные файлы. Деплой согласовывать отдельно.
- Каждое сообщение в чате по проекту начинать с актуального процента **полного запуска** Букера в формате с двумя знаками после запятой (например, «Готовность проекта: 55,00%.»). В статусных сводках рядом показывать ещё две отдельные шкалы: технический MVP и красивый сайт с дизайном. Источник трёх оценок и фиксированных весов — `docs/PROJECT_PROGRESS.md`; прежняя общая оценка 84% заменена пересчётом полного запуска от 02.10.2026. После завершения критерия из любого реестра сразу пересчитывать затронутые проценты и показывать изменение в процентных пунктах и остаток. Не начислять баллы за один лишь тест, работу в процессе, незавершённый gate или повторно за уже учтённый результат. Формат сотых не означает точность прогноза.
